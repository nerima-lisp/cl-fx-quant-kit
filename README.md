# fx-quant-kit

`fx-quant-kit` is a pure Common Lisp toolkit for quantitative finance and FX
analysis.  It has one public package, `FX-QUANT-KIT`, and keeps calculation
code independent from databases, brokers, network access, wall-clock time,
and persistence.

## Scope

The library provides:

- validated numeric vectors, descriptive statistics, returns, quantiles, and
  normal-distribution functions;
- market quote, tick, and OHLCV value types with timestamp conversion;
- currency, currency-pair, cross-rate, forward-rate, P&L, and pip-value
  calculations;
- SMA, EMA, Wilder average, RSI, MACD, Bollinger Bands, ATR, Hurst, GARCH(1,1),
  and realized volatility;
- Black-Scholes/Garman-Kohlhagen prices, option contracts, Greeks, implied
  volatility, discount factors, and forward prices;
- deterministic seeded simulation for geometric Brownian motion and
  Ornstein-Uhlenbeck processes, plus streaming Monte Carlo estimation;
- historical and parametric VaR/expected shortfall, Kelly sizing, volatility
  targeting, drawdown, portfolio variance, risk contributions, and stress
  loss;
- JSON boundaries for the value types.

The implementation uses `cl-date-kit` for timestamp conversion,
`cl-json-kit` for JSON encoding/decoding, and `cl-prolog` for declarative rule
evaluation.  Tests use `cl-weave`; structural Lisp checks use `paredit-cli`.
The Nix environment is assembled with `cl-nix-forge` and `treefmt-nix`.
These are direct dependencies because the corresponding APIs are called by the
source, test harness, or development environment.  Database, broker, network,
dataflow, boundary-adapter, and application-layer packages are not runtime
dependencies: this library has no I/O boundary for them to implement.

## Quick start

Load the ASDF system and use the single public package:

```lisp
(asdf:load-system "fx-quant-kit")
(use-package "FX-QUANT-KIT")

(mean #(1d0 2d0 3d0))
(black-scholes-price 100d0 100d0 1d0 0.2d0 0.03d0)

(let ((pair (make-currency-pair "EUR" "USD")))
  (fx-forward-rate pair 1.10d0 0.02d0 0.04d0 0.5d0))

(let ((contract (make-option-contract :call 100d0 1d0)))
  (option-contract-price contract 100d0 0.2d0 0.03d0))
```

Inputs are validated at public boundaries.  Numeric functions return
double-float values or simple vectors; value objects are immutable by
convention after construction.  Random simulations require an explicit
`simulation-rng`, so reproducibility does not depend on global state.

## Contracts

- Rates, volatilities, prices, and notional values use annualized or quoted
  units documented by each function.
- FX pairs mean quote currency per base currency.
- VaR and expected shortfall are positive loss amounts.
- Black-Scholes time-to-expiry and volatility are strictly positive; expiry
  boundary pricing is intentionally a separate concern.
- Errors are signalled as exported conditions such as `invalid-argument`,
  `invalid-shape`, `insufficient-data`, and `numerical-error`.

## Tests

The canonical local entry point is:

```sh
sbcl --script run-tests.lisp
```

The runner registers this checkout and inherits the caller's ASDF source
registry for the direct nerima-lisp dependencies.  A test run must report a
non-zero selected-test count; an empty selector is not success.

With Nix, the standard checks and development tools are available through:

```sh
nix develop
nix flake check --print-build-logs
nix build .#coverage
```

The Nix coverage output is generated by `cl-nix-forge`'s SBCL `sb-cover`
runner after force-loading the `fx-quant-kit` source; the test system remains
outside the reported source set.  Direct `cl-weave` coverage thresholds are
also available through `fx-quant-kit/test:run-tests`.

## Non-goals

This repository does not implement order execution, account or position
persistence, event sourcing, market-data transport, broker adapters, model
training, model serving, or trading application loops.  Adapters for those
concerns belong outside the calculation library.
